# LexiNote 产品需求文档（PRD）

**版本：** v1.3
**产品名称：** LexiNote  
**目标平台：** Android 优先  
**产品定位：** AI 辅助英语词汇查询、笔记记录与复习工具。

---

## 一、产品概述

LexiNote 旨在帮助用户便捷地查询、理解、记录和复习英语单词及短语。

### 核心设计原则

- **词库优先**：查询时优先检索已保存的词汇。
- **AI 辅助**：按需补充释义、分析语境及提供学习建议。
- **按需记录**：单词与短语全量保存，用户勾选只控制各笔记显示，可后续修改。
- **结构化笔记**：通过树形结构组织笔记，支持共享词汇节点。
- **便捷操作**：减少从查询到记录的操作步骤。
- **本地优先**：优先保障本地笔记的管理和访问能力。

## 二、主要页面与功能

应用包含五个一级入口：

1. 查询和记录
2. 猜词辅助
3. 笔记
4. 复习
5. 我的

### 2.1 查询和记录

核心页面，负责词汇查询、AI 辅助理解、最近查询和笔记保存。

#### 2.1.1 查询输入

支持三种查询方式：

- **文本查询**：手动输入单词或短语。
- **图片查询**：拍照或选择图片，通过勾画区域指定查询内容。
- **图片 + 文本查询**：同时提交图片和文字，支持附加问题与查询要求。

#### 2.1.2 查询逻辑

- 优先查询本地已保存词库。
- 已有记录时展示现有信息，允许按需补充。
- 未找到记录时，通过配置的 LLM 获取查询结果。
- 图片输入由 AI 识别并整理文字内容。
- AI 可结合上下文解释单词或短语。
- 查询结果与笔记存储分离，未经用户确认不自动保存。

**v1.2 统一会话 Agent：**

- 明确的标准查询直接返回词条；框选多词、目标不明、识别模糊、图文冲突、纠错和中文查英文由同一个 AI 助手澄清。
- 尚未有词条时也可打开助手；澄清、语法/翻译等普通问答和词条后续答疑共用同一会话。
- Agent 返回受校验的 JSON 动作：澄清与候选、确认查询、直接回答、请求补充输入。候选选择不直接执行查询，推断或修正后的目标通过确认卡片执行。
- 确认卡片显示目标、单词/短语类型、来源片段及查询要求；用户可确认或修改。查询成功后展示结果并收起助手，保留完整对话；失败时保留卡片并允许重试。
- 原始图片、框选、识别文本、原始提问和已确认目标在查询全过程保留。修改源输入使旧卡片失效，需重新提交；修改目标可继续澄清。
- 模型输出格式错误最多修复一次；网络、模型配置和鉴权失败单独提示，不伪装成输入歧义。首版完整校验回复后展示，不展示可执行的部分 JSON。
- 默认手动保存；开启既有自动记录设置时仅对成功词条执行，普通答疑、未确认建议和失败结果不得入库。

#### 2.1.3 页面布局

查询页面主要由以下部分组成：

| 区域 | 功能 |
|---|---|
| 查询输入区 | 三种查询方式与提交入口 |
| 上方信息视图 | 展示查询结果、释义、例句、来源等 |
| 下方 AI 助手 | 针对当前查询内容进行对话 |
| 底部操作栏 | 整理笔记及选择保存位置 |

**交互要求：**

- 图片查询时，自动将 AI 识别整理的文字展示在信息视图最上方。
- AI 助手默认折叠，可展开为全屏对话界面。
- AI 助手能够获取当前查询上下文。
- 上方信息按字段展示，便于选择性保存。

#### 2.1.4 笔记记录流程

底部默认显示：

`[整理笔记]`

点击后进入整理模式，切换为：

`[添加到默认笔记] [选择添加笔记]`

整理模式下：

- 可勾选需要保存的字段，如中文释义、英文释义、音标、例句、来源片段、来源图片、批注及备注。
- 必填字段自动保存，不允许取消。
- 支持选择多个释义分别保存。
- 可以修改或补充待保存的内容。
- 可选择保存到默认笔记或多个指定笔记。
- 保存已有词汇时，按选择补充内容，避免不必要的重复与覆盖。
- 多个笔记引用同一词汇实体，不重复创建数据。

#### 2.1.5 最近查询

保留**最近 10 条完整查询会话**，包含尚无词条的澄清和普通答疑；每轮消息不单独占用历史名额。

**记录内容：**

- 查询 ID、查询时间、查询方式。
- 原始查询文本。
- 原始图片及勾画区域（如有）。
- 图片识别与整理后的文本。
- 完整查询结果及 AI 补充内容。
- 当前查询对应的 AI 助手对话记录。
- 笔记保存状态及保存目标。

**功能要求：**

- 查询页面提供最近查询入口。
- 支持恢复原始输入、对话和有效的待确认查询卡片；中断中的请求恢复为可重试状态。
- 支持浏览和重新打开历史查询。
- 打开历史记录时恢复查询内容与结果。
- 支持删除单条记录及清空历史。
- 最多保存 10 条，新增记录自动淘汰最旧记录。
- 最近查询持久化保存在本地，重启应用后仍可访问。
- 删除查询记录不影响已保存的笔记内容。

### 2.2 猜词辅助

通过语境帮助用户理解陌生单词或短语。

**主要功能：**

- 拍照或选择图片。
- 勾画需要猜测的单词或短语。
- AI 识别图片内容及上下文。
- 根据语境提供词义猜测提示。
- 支持逐步获取提示及查看最终解释。
- 支持将目标词汇及语境转入「查询和记录」页面。

**设计原则：** 优先引导用户结合语境自行理解，而不是直接展示答案。

### 2.3 笔记

负责查看、组织、维护、导出和备份已记录的知识。

#### 2.3.1 笔记管理

- 浏览全部词汇及笔记树。
- 创建、重命名、编辑、删除笔记。
- 支持笔记嵌套及节点归类。
- 查看和编辑词汇及含义记录。
- 支持编辑批注、备注和来源信息。
- 支持按名称、内容、类型、标签筛选与搜索。
- 支持将同一词汇添加到多个笔记。

#### 2.3.2 笔记树规则

- 初次启动自动创建默认笔记树。
- 永久存在一个包含全部词汇的全局视图。
- 允许存在多个自定义笔记树。
- 允许笔记嵌套笔记。
- 同一父节点的直接子节点类型必须一致，即只能是笔记或词汇节点。
- 同一词汇节点可被多个笔记树引用。
- 删除笔记中的引用不等于删除词汇实体。

#### 2.3.3 导出功能

支持根据当前筛选结果导出笔记。

- 根据名称、标签、类型等条件筛选。
- 仅导出当前筛选结果。
- 未设置筛选条件时可导出全部内容。
- 导出包含词汇及关联含义、批注、备注等信息。
- 导出格式为 Markdown / JSON，支持保存文件与分享，复制文本为辅助入口。
- 筛选导出不包含可恢复的完整笔记树或图片文件，不代替全量备份。

#### 2.3.4 备份功能

提供独立于筛选结果的全量备份。

- 一键备份全部笔记数据。
- 备份不受当前筛选条件影响。
- 包含所有笔记树、词汇、含义、批注、备注、标签、来源图片及节点引用关系。
- 包含最近 10 条查询记录。
- 支持从备份文件恢复数据。
- 不包含 API Key 等敏感凭据。
- 全量备份使用 ZIP 格式，数据版本为 2.1，包含无词条会话、结构化动作和待确认卡片，兼容 2.0 ZIP 与 1.0/1.1 JSON；内含引用图片文件和完整性校验信息。文件及解压后数据上限均为 50 MB。
- 恢复前校验版本、实体结构、笔记树及引用关系，并展示时间、词汇数、笔记数、查询数与图片数。
- 首版仅支持明确确认后的覆盖恢复；通用设置迁移，本机供应商连接和密钥保留。
- 写入前保存一份本机快照与恢复日志；失败回退，意外退出后优先从日志回退；支持手动回到上次恢复前。
- 兼容 1.0 / 1.1 JSON 文件和旧版剪贴板备份。旧 JSON 未打包图片，恢复预览须明确提示跨设备图片限制。
- 取消操作不提示备份成功；系统分享与浏览器下载不作为已确认保存记录。

**区别：** 导出用于选择性提取内容；备份用于完整保存与恢复应用数据。

### 2.4 复习

预留页面，具体功能暂不设计。

### 2.5 我的

主要包含应用设置与数据管理入口。

- LLM 供应商配置。
- 外观设置。
- 查询与自动记录偏好。
- 数据备份与恢复。
- 应用信息。

## 三、设置功能

### 3.1 LLM 供应商配置

参考 DeepTutor 的供应商与模型配置机制，采用可扩展结构。

#### 当前默认配置

| 配置项 | 默认值 |
|---|---|
| 供应商 | DeepSeek |
| API 格式 | OpenAI Compatible |
| Base URL | `https://api.deepseek.com` |
| Model ID | `deepseek-flash`（预设，需验证可用性） |
| API Key | 用户自行填写 |

#### 配置要求

- 默认展示预设供应商与模型。
- 支持勾选「自定义 Base URL」。
- 支持勾选「自定义 Model ID」。
- API Key 默认隐藏，支持安全修改与清除。
- 支持测试连接。
- 允许未来添加其他供应商及模型。
- 底层区分供应商配置、模型配置及当前启用模型。
- 图片识别需要模型具备视觉理解能力，不支持时提示用户切换模型。

#### 安全要求

- API Key 使用 Android Keystore 支持的安全存储机制保护。
- 密钥不以明文写入普通配置文件、日志或备份。
- 模型调用使用 HTTPS，自定义服务地址需进行安全校验。

### 3.2 外观设置

- 主题模式：浅色、深色、跟随系统。
- 主题强调色：预设颜色选择。
- 字体大小：支持调整。
- 显示密度：舒适、紧凑。

### 3.3 查询与记录偏好

- 默认笔记选择。
- 默认勾选保存的字段。
- 自动记录额外信息开关。
- 查询结果展示偏好。

### 3.4 数据管理

- 全量备份与恢复。
- 按筛选条件导出笔记。
- 导入已有备份。
- 清空最近查询记录。
- 本地数据管理。

## 四、核心数据结构

### 4.1 笔记树（Notebook）

| 字段 | 要求 |
|---|---|
| id | 必填，唯一标识 |
| name | 必填，名称 |
| created_at | 必填，创建时间 |
| updated_at | 必填，修改时间 |
| tags | 可选，多个标签 |
| children | 子节点引用关系 |

**关系规则：**

- 笔记树允许嵌套。
- 同一父节点的子节点类型必须统一。
- 词汇节点通过引用关系归属笔记。
- 全局根为系统维护的特殊视图。

### 4.2 词汇节点（Vocabulary）

| 字段 | 要求 |
|---|---|
| id | 必填，唯一标识 |
| type | 必填，单词/短语 |
| content | 必填，词汇内容 |
| created_at | 必填，创建时间 |
| updated_at | 必填，修改时间 |
| tags | 可选，多个标签 |
| meanings | 必填，至少一条含义 |

### 4.3 含义记录（Meaning）

| 字段 | 要求 |
|---|---|
| id | 必填，唯一标识 |
| created_at | 必填，创建时间 |
| updated_at | 必填，修改时间 |
| zh_definition | 中文释义，可选* |
| en_definition | 英文释义，可选* |
| phonetic | 音标，可选 |
| example | 例句或来源片段，可选 |
| source | 来源信息，可选 |
| source_images | 来源图片，可选，支持多张 |
| annotations | 批注集合，可选 |
| remarks | 备注文本，可选 |

*中文释义和英文释义至少填写一项。*

**批注与备注区别：**

- **批注（Annotation）**：针对某项释义、例句或来源片段的补充解释，支持多条及定向关联。
- **备注（Remarks）**：针对当前含义记录的自由文本补充，不要求关联具体字段。

#### 批注（Annotation）字段

| 字段 | 要求 |
|---|---|
| id | 必填，唯一标识 |
| meaning_id | 必填，所属含义 ID |
| target_field | 可选，批注目标字段 |
| target_text | 可选，被批注的文字片段 |
| content | 必填，批注内容 |
| created_at | 必填，创建时间 |
| updated_at | 必填，修改时间 |

### 4.4 最近查询记录（QueryHistory）

| 字段 | 要求 |
|---|---|
| id | 必填，唯一标识 |
| created_at | 必填，查询时间 |
| query_type | 必填，查询方式 |
| input_text | 原始输入文本，可选 |
| input_images | 原始图片，可选 |
| selected_regions | 图片勾画区域，可选 |
| recognized_text | 图片识别结果，可选 |
| query_results | 可选，成功后的完整词条结果 |
| ai_messages | AI 助手完整对话记录 |
| revision / session_state | 会话输入版本与处理状态 |
| pending_lookup | 可选，绑定消息与输入版本的待确认查询 |
| saved_content | 已保存内容及目标信息 |

**存储规则：**

- 本地持久化。
- 最多保留最近 10 条。
- 按查询时间排序。
- 新增第 11 条时自动删除最旧记录。
- 保留原始输入与完整结果快照。
- 查询记录与正式笔记数据相互独立。

### 4.5 数据关系

- 一个 Vocabulary 可以包含多个 Meaning。
- 一个 Meaning 可以包含多个 Annotation。
- 一个 Meaning 可以关联多个来源图片。
- 一个 Vocabulary 可以被多个 Notebook 引用。
- 全局词汇视图自动聚合所有已保存词汇，不重复存储实体。
- QueryHistory 独立保存查询过程和结果，可以引用已保存词汇。

## 五、基础运行规则

1. **本地优先**：笔记与已保存词汇在本地持久化，支持离线查看、编辑与检索。
2. **AI 按需调用**：AI 查询、图片理解和对话需要网络及有效的模型配置。
3. **显式保存**：查询结果不会直接写入词库，除非用户确认保存或开启明确的自动保存设置。
4. **字段级保存**：允许选择保存内容，未选字段不自动写入。
5. **避免重复**：已有词汇优先补充或引用，避免创建重复实体。
6. **统一更新**：共享词汇的数据修改会反映在所有引用该词汇的笔记中。
7. **查询记录独立**：最近查询保留完整历史快照，不随笔记修改自动覆盖。
8. **数据可迁移**：备份与恢复必须保留词汇、含义、批注、备注、标签、图片、查询历史及笔记引用关系。

## v1.3 页面、会话与笔记修订（优先于前文旧版字段保存描述）

查询记录首页与查询信息页分离；查询区以图文模式统一固定高度，结果页不显示首页顶栏、查询区和 Tab，返回首页才能查新词。AI 助手固定全屏，会话入口位于首页查询区下方。

AI 动态提供最多三个追问，点击填入而不自动发送。助手支持主动保存、手动命名及采用 AI 名称候选，创建/最近使用时间由存储服务维护。临时会话自动命名，最多五个，LRU 淘汰，空草稿不占位；保存会话不受此限制，按名称、创建或最近使用日期组合检索。

进入历史默认定位最新消息；上翻保留位置，圆形悬浮按钮回到底部。新查词提案从助手返回首页，经显式确认执行。

完整保存全部已获取的单词、短语和释义字段；不同笔记独立配置显示的释义和字段，后续可调整。备注绑定每条释义，允许同一释义多条备注。旧版已经丢弃的未保存字段无法凭空恢复，可重新查询补充。

实现与验收见 [统一查询与会话](QUERY_AGENT.md) 及 [实施计划](superpowers/plans/2026-10-23-query-pages-and-ai-conversations.md)。
