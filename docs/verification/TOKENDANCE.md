# TokenDance 迁移验收（2026-10-28）

原生 Java 版本以 `22a8362` 为基线，按原 Expo 版本的授权和支付接口继续迁移。本次没有使用真实 TokenDance 账户，没有调用付费模型，也没有创建真实充值订单或执行支付。

## 已接入

- 默认设置卡片提供连接/重新授权、账户与密钥、充值、调用记录及使用帮助。基础 TokenDance 模型和密钥配置直接展示，其他供应商和手动参数仍收在高级设置中。
- 内置原版 2026-10-22 核对的 34 个图像理解模型及 53 项排除表，支持断网搜索选择；未知模型需要显式自定义标记，已知不兼容模型仍被拒绝。这个列表来自本地原版，不是本轮对线上模型能力的重新认证。
- PKCE S256、随机 state、10 分钟有效期、严格 HTTPS callback 和重复参数校验。在应用内的网页拦截预期回调；系统浏览器使用新的无回调授权流程，返回应用粘贴一次性授权码。密钥交换和服务激活后自动返回设置页。
- 授权 verifier/state 与充值会话（包括支付链接）仅在设备加密存储中保存，不进入应用备份、Activity Bundle 或日志；激活官方服务、保存密钥和清除待授权状态使用一次提交。重新配置密钥清除旧充值会话，避免跨账户沿用。
- 原生充值页支持整数金额、创建会话、用户确认后打开支付宝、返回应用检查状态，以及终态/到期处理。轮询结果缺少支付链接时保留原链接；本地到期仍先核对服务端状态，不把已支付但晚返回的订单误判为过期。创建过程中被中断会给出明确提示，重新创建前要求确认。
- 正式网关的恢复响应可区分余额不足、授权失效与周期额度用尽，查询和连接测试提供对应充值/重新连接入口。其他供应商不能通过相同响应头触发 TokenDance 恢复流程。
- 密钥输入支持显示/隐藏；原生门户控件跟随应用主题、字号和强调色。

## 使用与剩余验证

在「我的」选择「连接 TokenDance」并登录授权；应用内回调可自动完成。若转到系统浏览器，完成授权后返回粘贴一次性授权码。也可继续手动填写 API Key。充值仅在点击并确认打开支付宝后由用户操作。

已在模拟器打开真实授权入口，观察到外部网站 watcha.cn 的跳转提示和系统浏览器继续入口；未输入账户信息。真实登录/验证码、授权交换和支付结算尚未实测。Android 系统浏览器的自动 App Link 返回仍属于原 Expo 包的域名关联，本 Java 包采用一次性码方式；没有声称已经为新包配置网站域名关联。账户、调用记录和帮助使用服务网站；其内容和可用性取决于服务端。

内嵌网页没有 JS bridge、不会注入 API Key/verifier，并禁用文件、内容 URI 和明文混合内容。外域主页面交系统浏览器继续，直接外域主框架请求在拦截回调中处理，重定向还会阻止显示；不声称能够撤回已经发出的重定向/POST 请求。该实现遵循 [Android WebViewClient 导航回调的边界](https://developer.android.com/reference/android/webkit/WebViewClient)，没有将网页导航回调当作完整网络隔离。

本次 APK 使用现有 Android Debug 签名，大小 1,461,458 字节，SHA-256：`86F4AFC93BF235518A9842AB03FCF1009E3E0D702549248FE5AEFFB9A0E20FAC`。真实设备、支付宝客户端、Android 8 设备和整套深色/大字号交互仍待进一步验收。
