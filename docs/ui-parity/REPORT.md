## 对比条件

同一 Pixel_9a 模拟器、Android API 37、1080 × 2424、420dpi，默认浅色外观、标准字号。包名分别为 `com.lexinote.app` 和 `com.lexinote.nativeapp`。原版使用当前源仓库离线构建的 Release APK；核对打包 sourcemap 中首页、查询区、复习页的源码内容与工作区一致，源仓库未修改。

空数据状态覆盖首页文字查询、图片查询、图文+提问、猜词、笔记、复习、设置、空助手共8种状态；含数据状态覆盖词条、助手、笔记、复习准备共4种状态，共12组截图。截图原图和对应 UI accessibility XML 分别保存在 `reference/` 与 `after/`；`before/` 保留调整前五入口。状态栏时钟、系统手势栏及拍摄时的触摸/光标状态不参与布局判断。

含数据测试使用 [fixture.json](fixture.json) / [fixture.zip](fixture.zip)：同一个 resilient 词条、两条中英文释义与例句、默认笔记和全局词库、一个保存会话、两条消息、一条历史。ZIP 由原版实际 `encodeBackup` 生成并经原版文件恢复入口成功导入；不含图片、密钥或用户个人数据。原生截图临时载入同一 JSON，脚本结束后恢复截图前的应用数据。

## 调整与差异

| 页面 | 本次对齐的主要布局 | 仍存在的差异 |
| --- | --- | --- |
| 全局 | 白色紧凑标题栏、浅灰页面背景、同一 Ionicons 字体、五个图标 Tab、原版主题配色 | Android 原生文字度量/字重、圆角、阴影存在差异；底栏保留系统手势安全区 |
| 首页 | 312dp 三模式查询卡、上下文框、已保存会话与临时会话两卡、日期筛选、最近查询页头入口 | 模式按钮与字体细节、列表日期格式不同；高级图片编辑能力仍见迁移说明 |
| 图片/图文 | 并排相机/相册选择块、图标圆底、固定查询按钮、图文模式目标输入 | 相机使用系统缩略图；原版框选工具的完整编辑界面未等价迁移 |
| 猜词 | 原则说明、图片/文字分段、图片占位框、相机/相册按钮、主操作按钮 | 四阶段提示卡的动画和细节排版不同 |
| 笔记 | 固定搜索导出栏、横向分类、当前分类栏、类型筛选、紧凑词汇卡、空态 | 原版标签筛选与批量管理未完整迁移；列表释义展开程度和管理入口不同 |
| 复习 | 三列统计、空态、范围选择、两张模式卡、10/20/50等宽选项、独立开始按钮 | 原版拼写测验未迁移；原生看义猜词使用答案揭示和评级 |
| 设置 | 服务概览、独立高级配置入口、主题/六色强调色/字号/密度选择、偏好与备份 | 原生服务概览替代 TokenDance OAuth/账户卡，因此顶部卡片内容和高度明显不同；密度尚未影响所有原生控件 |
| 词条 | 词头/类型/本地状态/音标、编号释义、双语灰底块、例句、底部助手入口和整理按钮 | 原版 AI 补充入口和就地编辑未完整迁移；原生仍使用整理对话框 |
| 助手 | 顶部名称与保存入口、白底、用户/助手圆角气泡、底部输入框和圆形发送按钮、追问候选 | 消息宽度、Markdown、长列表和键盘行为仍有差异；不是流式输出 |

## 复现

安装原版与原生 APK 到专用测试模拟器，依次执行：

```powershell
./scripts/capture-ui-parity.ps1 -Stage reference
./scripts/capture-ui-parity.ps1 -Stage after
# 在原版“我的 → 从文件恢复”导入 fixture.zip，取得含数据截图。
./scripts/capture-native-populated.ps1
python scripts/compare-ui-parity.py
```

含数据原版入口：保存会话打开助手；最近查询打开词条；笔记/复习 Tab 打开其准备页面。原生含数据脚本只适用于 debug 包，使用 `run-as` 备份并还原私有 JSON，不操作供应商凭据。截图前应使用独立测试数据；原版恢复入口会明确确认覆盖，并自动保留恢复前快照。

`node scripts/create-ui-parity-fixture.cjs <原版目录>` 可重新生成同一备份。生成器依赖原版现有 Node/TypeScript，仅用于审计；原生项目本身的构建和测试不依赖原版工程。
