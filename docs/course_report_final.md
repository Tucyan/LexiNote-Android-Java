### 摘  要
针对移动学习场景中查词依赖网络、释义脱离语境以及生词复习缺乏科学排期等问题，本系统设计并实现了一套基于 Android Java 原生技术的智能英语词汇学习与间隔复习系统（LexiNote）。系统按照模块化架构划分为查询记录、笔记管理、复习中心及系统设置四个核心子系统。在离线环境下，应用基于内置 ECDICT 词库与 Sherpa-onnx 神经语音合成技术实现毫秒级单词检索与离线发音；在具备网络连接且用户授权时，可通过标准接口调用外部大模型进行语境深度解析与多轮问答。

系统表现层由 `MainActivity`、`TokenDanceActivity` 与独立图像编辑组件 `ImageEditorActivity` 协同构建，主导航采用原生 View 模块化控制器管理；数据持久层基于 SQLite 采用世代分区架构，确保词汇实体、笔记引用关系与学习轨迹的持久化与一致性，同时支持防路径穿越的安全 ZIP/JSON 数据备份与原子恢复。基于 SM-2 记忆曲线思想设计的改进型复习算法，通过离散三档评级与动态间隔排期，有效提升了词汇记忆保持率。运行测试表明，系统具备良好的运行稳定性和操作流畅度，满足移动学习应用的设计与工程要求。

**关键词**：Android平台；离线词库检索；神经网络语音合成；SM-2算法；间隔重复；数据持久化

### 3 作品可行性分析与市场前景

#### 3.1 目标群体与典型使用场景
1. **备考学生群体（四六级、考研、托福雅思）**：刷题中遇到长难句生词，需结合特定上下文精准取词并纳入复习计划；
2. **专业文献与泛阅读者**：在无网（如航班、地下铁、图书馆弱网）环境下快速查阅专业词汇并收听标准离线发音；
3. **日常多媒体学习者**：阅读英文书籍、论文时通过截屏或拍照，快速框选定位目标生词并提取学习；
4. **长期词汇积累者**：需要对多年积累的词库进行分类管理与安全备份，避免受制于单一商业软件账号。

#### 3.2 市场前景与竞品差异化分析
当前移动端英语学习市场主要以商业 App 为主，各竞品优缺点与 LexiNote 的差异化对比如下：

| 维度 | 传统商业词典（如某道/某霸） | 商业背单词软件（如某斩/某墨） | **LexiNote 智能学习笔记** |
| :--- | :--- | :--- | :--- |
| **网络依赖** | 核心释义与发音高度依赖联网，离线包庞大且功能受限 | 每日打卡与词库更新依赖在线服务器 | **离线优先设计**：ECDICT 数据库与 Sherpa-onnx 神经 TTS 均内置，无网体验完整 |
| **语境理解** | 仅提供预设离线静态例句，无法针对用户输入的特定句子展开分析 | 仅按照既定词书背诵，无法即时解析外部文献中的生造搭配 | **双核协同**：支持用户自主授权外部大模型，针对复杂长难句进行上下文定制化义项解析 |
| **商业与数据** | 广告与开屏推送较多，用户单词数据绑定平台账号 | 设定收费词书与付费上限，数据难以导出到本地 | **纯净与自主可控**：无广告干扰，数据存储在本地 SQLite，支持标准 ZIP 安全导出与跨设备迁移 |
| **复习机制** | 查词与复习脱节，缺乏科学艾宾浩斯复习流 | 算法封闭，评分繁琐，复习范围受限于官方词库 | **透明改进型 SM-2 算法**：深度融合自建笔记树，支持单词再认与拼写回想双模式自测 |

#### 3.3 技术可行性分析
1. **Android 原生框架支持**：Android SDK 提供了成熟的 Activity 生命周期调度、SQLite 数据库引擎、相机/相册 SAF 框架与 AndroidKeyStore 硬件级加密库，底层支撑完备；
2. **轻量高效的离线生态**：ECDICT 词典经过 SQLite 索引优化后体积小巧（约 30MB 左右），检索延迟 $\le 5\text{ms}$；Sherpa-onnx 离线引擎提供了高质量移动端 CPU 神经语音推理能力；
3. **安全规范的网络交互**：采用标准 HTTPS + SSE（Server-Sent Events）实现与云端 LLM 的流式交互，结合 RFC 7636 PKCE OAuth 协议，保障了云端协同的技术可行性。

#### 3.4 非功能需求与设计约束
- **数据可靠性**：所有学习记录与复习事件采用本地事务提交；备份恢复机制具备原子性，导入异常时自动回滚，确保现有数据不受破坏；
- **凭据安全性**：网络通信全量强制 HTTPS（`usesCleartextTraffic=false`）；第三方 API Key 经 AndroidKeyStore AES-256-GCM 硬件加密存储，严禁打包进备份归档；
- **系统高可用**：查词、发音、笔记与复习四大核心流程在无网环境下具备 100% 可用性；
- **平台兼容性**：支持 Android 8.0（API 26）及以上系统，构建目标适配 Android 16（API 36），采用 Java 17 编写，确保在主流机型上的平稳运行。

#### 3.5 验收指标与功能优先级
- **P0（核心必备）**：断网状态下快速检索 ECDICT 词典；词汇归档至笔记本；基于改进型 SM-2 完成复习与排期持久化；
- **P1（高阶扩展）**：全屏 `ImageEditorActivity` 图像编辑与标注；具备网络时的大模型语境深度解析；完整 ZIP 备份导出与数据恢复；
- **P2（体验打磨）**：大词库多维排序与语义检索；流式打字机显示效果；主题切换。

### 4 概要设计与系统架构

#### 4.1 开发环境与技术栈选型
- **开发语言**：Java 17；
- **构建环境**：Gradle 8.13 + Android Gradle Plugin 8.13.2；
- **SDK 配置**：`compileSdk 36`，`targetSdk 36`，`minSdk 26`；
- **界面架构**：原生 Android View 层次结构 + 模块化视图控制器；
- **本地持久化**：Android 原生 SQLite + 世代代次分区架构；
- **离线能力库**：ECDICT 嵌入式词典库、Sherpa-onnx 离线神经语音库。

#### 4.2 整体技术架构设计
系统遵循分层架构原则，自上而下分为表现层（Presentation Layer）、领域业务层（Domain Business Layer）、数据访问层（Data Access Layer）以及底层基础资源层（Infrastructure Layer）。

#### 4.3 核心 Android 组件与页面导航
为满足系统功能独立性并符合 Android 规范，系统注册并运行了 **3 个核心 Activity 组件**：
1. **`MainActivity`**（主界面）：配置 `LAUNCHER` 意图过滤器，作为应用根容器，承载底部等宽四栏导航（查询记录、笔记、复习、系统设置）及各模块视图控制器的调度；
2. **`TokenDanceActivity`**（OAuth 认证回调组件）：配置专属深层链接（Deep Link）意图过滤器，专门用于接收系统浏览器 OAuth 2.0 PKCE 鉴权完成后的重定向回调，完成令牌安全置换；
3. **`ImageEditorActivity`**（独立图像编辑组件）：在功能分支 `codex/image-editor-activity` 中，为保证复杂图像编辑（旋转、裁切、框选、多画笔标注）拥有独立的生命周期并规避内存抖动，图像编辑器被重构为一个独立的全屏 Activity。它通过 `registerForActivityResult` 接收输入图片 Uri，在独立的窗口生命周期中维护手势与选区状态，完成后将裁剪后的结构化数据回传给主页面。

#### 4.4 数据模型与逻辑结构
数据层设计平衡了移动端的灵活性与结构化查询性能：
1. **词汇与笔记模型**：词汇实体（`Vocabulary`）作为全局独立对象持久化；笔记本（`Notebook`）通过父子 ID 构建树形层级；两者之间建立独立的 `NotebookReference` 关联，实现“单条词汇多笔记本共享引用”，确保从某一笔记本移除引用不会误删全局词汇；
2. **复习状态模型**：由计划（`ReviewPlan`）、单词复习状态（`ReviewState`）及事件记录（`ReviewEvent`）构成。每个单词的复习状态记录难度因子（EF）、复习轮次、当前间隔天数及下一次到期时间戳；
3. **世代分区存储结构**：SQLite 数据库中引入 `generation` 字段，以代次提升方式管理数据迁移与快照恢复，有效保证了数据升级与恢复操作的原子性。

### 5 详细设计与实现、流程图、难点及特色分析

#### 5.1 查询与离线词典模块
系统查词遵循“离线优先、按需增强”的工作流机制：
1. 用户输入目标单词后，系统先在本地个人笔记库中比对；
2. 未命中时，在后台线程检索只读 ECDICT SQLite 数据库。检索采用词形标准化处理，若主表未命中，自动检索 `variant` 词形变化表，还原动词过去式、名词复数等原形词条（例如输入 `went` 自动匹配到 `go`）；
3. 若用户输入了附带语境的例句或主动触发“联网核对”，系统通过 `AiClient` 异步拉取云端大模型对该句子的特定释义进行解析；本地词典释义与 AI 生成语境分析在卡片上明确分层展示，互不干扰。

#### 5.2 图像处理与 ImageEditorActivity 独立组件
在 `codex/image-editor-activity` 分支中实现的独立图像编辑组件包含以下核心技术：
1. **归一化坐标几何变换**：为适应移动设备不同屏幕分辨率与屏幕旋转，用户在屏幕上的手势选区与画笔笔迹（`inkStrokes`）均被实时换算为相对于原图的归一化浮点坐标（$0.0 \sim 1.0$）；
2. **双缓冲手势渲染与撤销栈**：`ImageCropView` 维护不可变的 `ImageEditorState` 历史快照栈，支持最多 128 笔独立涂抹轨迹与最高 8192 个坐标点的回退与重做；
3. **组件独立性与内存保护**：作为独立 Activity 运行，使得大尺寸 Bitmap 缩放与旋转操作隔离在专属进程窗口中，避免了大图编辑对主界面主线程消息队列的内存挤占。

#### 5.3 AI 服务调用、模型配置与会话管理
1. **流式传输与异步解析**：云端交互采用 SSE（Server-Sent Events）长连接，服务端流式返回 Token 片段并在界面上通过轻量打字机队列平滑渲染；
2. **自动标题生成的竞态防护（`TitleSuggestionGuard`）**：针对 AI 异步概括会话标题耗时较长的问题，设计了防覆盖守卫机制。系统在发起请求时记录当前会话的 `revision`（修订号）与 `epoch`（生命周期纪元）。当网络结果返回时，仅当用户未手动重命名且当前会话未被删除、未发生版本变更时，才允许写入建议标题，消除后台迟到响应覆盖用户手动命名的并发风险。

#### 5.4 笔记管理、组织与多维检索
1. **树形笔记本与级联控制**：系统支持多级子笔记本创建，并在领域层施加约束：系统内置根笔记不可嵌套；已有词汇的笔记本不可与子笔记本混用，确保知识分类树结构清晰；
2. **语义投影检索索引（`NotebookSearchIndex`）**：为杜绝直接基于数据库 JSON 字符串匹配带来的键名假阳性问题，系统为词汇建立了纯文本语义投影。检索时仅比对单词原型、词性、中英文释义、例句与批注，并支持输入时实时高亮响应。

#### 5.5 科学复习与改进型 SM-2 状态更新机制
针对移动端学习碎片化特点，系统基于 SuperMemo SM-2 算法进行了自适应离散改进：
1. **三档自适应离散评定**：将传统 0~5 的六级评分精简为更契合移动端单手操作的三级评定：
   - **再次（Again）**：表明遗忘，重置连续正确次数，难度因子 $EF = \max(1.3, EF - 0.2)$，排期间隔重置为 0 天（当日即时重练）；
   - **困难（Hard）**：记忆模糊，微调 $EF = \max(1.3, EF - 0.15)$，安排紧凑间隔（第 1 次 1 天，第 2 次 2 天，后续为旧间隔 $\times 1.2$）；
   - **简单（Easy）**：熟练掌握，提升 $EF = \min(3.0, EF + 0.1)$，安排较长跨度间隔（第 1 次 3 天，第 2 次 6 天，后续为旧间隔 $\times EF$）；
2. **幂等提交状态机**：每次评分生成全局唯一 `event_id` 并由事务持久化至 SQLite。界面在收到持久化确认后才推入下一词卡，杜绝了快速连击导致的重复计分。

#### 5.6 本地 SQLite 数据持久化与代次一致性
持久层采用 `LibraryDatabase` 管理模式定义。数据写入执行严格的事务控制：
- 引入 `store_meta` 维护当前活跃代次（`active`）、前序代次（`previous`）与下一代次（`next`）；
- 数据修改以原子事务提交，在代次切换前必须经由 `StreamingLibraryValidator` 完成完整性校验；
- 索引覆盖了会话排序与实体索引，支撑了上千条词汇下的流畅查询。

#### 5.7 数据备份、密钥安全隔离与可靠恢复
1. **Zip Slip 安全防御**：在 `BackupStreamCodec` 中，解压还原 ZIP 归档时对每一个文件的相对路径进行白名单模式校验（`validPath`），严禁包含 `../` 越界路径或绝对路径，从根源上杜绝了利用恶意备份包覆盖系统私有目录文件的安全风险；
2. **API 密钥硬件隔离**：`SecureSettings` 将服务配置（地址、模型名称）与身份凭据（API Key）分表管理。Key 使用 Android 硬件支持的 `AndroidKeyStore` 生成 AES-256 密钥并采用 GCM 模式加密持久化；数据导出时统一经过脱敏过滤器，确保导出的备份 ZIP 绝不包含任何明文私密密钥。

### 8 软件使用说明书

#### 8.1 软件概况与环境配置
- **运行环境**：Android 8.0（API 26）及以上版本的手机或模拟器；
- **工程构建**：使用 Android Studio 打开工程根目录，配置 JDK 17，执行 Gradle 同步后即可直接运行；
- **四大主模块**：底部导航栏均匀分布四大入口：
  1. **查询记录**：文本查词、图像选区取词、语境解析与历史查询抽屉；
  2. **笔记**：书架管理、多层级分类树、多维排序与语义检索；
  3. **复习**：基于改进型 SM-2 的每日复习队列、卡片翻转与掌握度自测；
  4. **我的**：服务授权配置、推理模式选择、语音引擎切换与数据安全备份。

#### 8.2 TokenDance 账号授权与配额管理
1. 切换至“我的”界面，在“AI 服务·词元跳动”卡片中点击“连接 TokenDance”；
2. 系统唤起外部浏览器打开统一授权页面，选择账号登录；
3. 在授权确认页中设置额度限制，点击“授权并创建密钥”；
4. 鉴权通过后浏览器重定向唤回应用内的 `TokenDanceActivity`，界面提示“已连接”即可使用。离线功能完全独立，无需登录即可长期正常使用。

#### 8.3 文本查词、图像框选与 AI 语境助手
1. **文本输入**：在查词输入框中输入目标单词，若有阅读原句可粘贴至下方“上下文例句”框内，点击“智能查询”；
2. **查看释义**：界面毫秒级展示本地音标与释义；具备网络时，卡片展示 AI 针对该原句的精准语境解读；
3. **图像取词**：点击“图片查询”，通过系统相机拍摄或相册选取图片，进入全屏 `ImageEditorActivity`。拖动边框完成生词选区，点击“完成”即可自动提取文字并进入查询流程；
4. **存入笔记**：在释义卡片底部点击“整理笔记”，勾选需要展示的释义字段与目标笔记本，点击保存。

#### 8.4 笔记管理：书架分类、多维排序与批量维护
1. **新建笔记本**：在“笔记”首页点击“新建分类”，输入名称并设定所属层级（支持子笔记本）；
2. **多维排序与展示**：顶部支持 7 种排序方式（A-Z、最新添加、生词优先等）与 3 种释义呈现方式（中文释义、英文释义、隐藏释义）；
3. **语义检索**：在搜索栏中输入单词、音标、释义关键词或例句片段，系统实时高亮筛选结果；
4. **批量操作**：点击“批量管理”进入多选模式，支持一键批量转移笔记本或安全删除引用。

#### 8.5 复习中心：记忆排期与双模式复习强化
1. **启动计划**：进入“复习”页，滑动选择目标复习计划（如四级核心词汇），点击“开始复习”；
2. **单词再认模式（看词猜义）**：卡片正面呈现英文单词，回想中文含义后点击翻卡查看答案；根据实际掌握程度，点击底部的“再次”（<10分钟重练）、“困难”或“简单”三档评价按钮；
3. **词义回想模式（看义猜词）**：卡片正面显示中文释义与词性线索，在拼写框中键入完整英文字符后提交判定。系统根据答题结果实时更新下一次到期时间戳与记忆因子。

#### 8.6 系统设置、数据备份与跨设备迁移
1. **数据备份导出**：进入“我的” $\to$ “数据与存储”，点击“导出完整备份”。系统调用 Android 存储访问框架（SAF），用户指定本地存储路径后生成 `.zip` 格式归档。归档内排除个人 API 密钥，保障数据流转安全；
2. **跨设备恢复**：换机后在新设备上点击“恢复数据备份”，选择历史 `.zip` 归档。系统首先校验 CRC 校验和与图片完整性，验证无误后以原子事务替换本地数据库，并刷新书架。
