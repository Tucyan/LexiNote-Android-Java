01ER · 词汇与笔记

同一个词汇只存一份，靠 id 被多个笔记引用；释义与批注则是内嵌结构，不能独立存在。

图 1内容模型：六张「表」，其中 meanings 与 annotations 实际是内嵌数组
  • 引用不是副本。notebooks.vocabulary_ids[] 只存词汇 id；把一个词「复制」到另一个笔记，实体仍然只有一条，改一处全线同步。
  • 显示配置按笔记走。vocabulary_display 的主键是 (notebook_id, vocabulary_id)，同一个词在不同笔记里可以显示不同释义子集。
  • 两个系统笔记由代码补建。nb_default 与 nb_global_root 在每次加载时校验，后者每次从全库词汇重建 vocabulary_ids。
  • 笔记树不能混装。一个笔记要么放子笔记（children_type = notebook），要么放词汇，二者互斥。

02ER · 会话与复习

活动数据全部挂在词汇上，但只有复习计划绑定了笔记；会话与最近查询是两套并存的存储。

图 2活动模型：会话域（蓝）与复习域（琥珀），左侧两个虚线框是图 1 的引用目标
  • 复习是子文档。library.json → review 下四个集合全部以 plan_id 为轴；states 与 days 是复合主键。
  • 最近查询不是会话本体。recent_queries 存的是同一 id 的完整副本，删掉它只会连带清掉失去索引的 query 会话，不影响 saved。
  • 历史不级联删除。词汇被移出笔记后，states 与 events 仍在，只是不再进队列、也不能再评分。
  • 事件即幂等键。review_events.id 就是 eventId，一次评分最多一条记录，重试不会翻倍。

03状态转换 · 文档在内存与磁盘之间

整份 JSON 只有这七个状态。日常使用几乎一直停在「脏」——它是正常态，不是异常。

图 3文档级状态转换：主循环在上，损坏与恢复分支在下
  • 「脏」是常态。每次输入或点按都会让内存领先磁盘，只有一次成功的提交才回到「一致」。
  • 失败不对称。提交失败时后端把 workingCopy 回滚，界面仍持有新快照，于是停在「脏」而两端短暂不一致。
  • 损坏是唯一阻断态。进入恢复页后 persist() 直接返回 false，业务侧完全没有写入能力。
  • 恢复与回退都换纪元。两者都执行 generation + 1，在途命令因世代不符被丢弃，旧数据无法覆盖新数据。

04状态机 · 会话留存

三种留存等级只升不降，淘汰就在每次写入会话时顺手完成。

图 4会话留存：右侧是升级路径，下方红虚线是自动淘汰
  • 只升不降。query → temporary → saved 没有反向转移；promoteTemporary() 遇到已保存的会话直接返回。
  • 淘汰是写时重算。没有定时任务，每次 touchSession() 都重建整个 conversations 数组。
  • 空会话不占名额。只打开助手又退出时仅改 metadata.origin，不会升级为 temporary。

05状态机 · 单次查询

状态不在 session_state 里，而由「哪个字段存在」表达。

图 5查询会话内部状态：两条进入「已有结果」的路径 + 一条追问回边
  • 字段即状态。query_results、pending_lookup、saved_content 三者决定界面落点；session_state 目前只会被写成 "ready"。
  • 提案会过期。pending_lookup 记录写入时的 revision，会话 revision 一变就判定失效，必须重新走流程。
  • 入库是幂等的。自动记录还要求开关打开，且 resultKey 与 auto_record_key 不同，同一份结果不会重复写。

06状态机 · 复习任务

「再次」不算完成：它把卡片送回队尾，当天还能再答一次。

图 6单张卡片在一天内的状态；跨日由 (plan_id, date) 重新组题
  • 两种评分，两种结局。再次 → completed 仍为 false 并移到队尾；困难 / 简单 → completed = true。
  • 掌握度只看完成。learned_at 仅在首次完成时写入，只答「再次」的词次日仍按新词处理。
  • 每日队列固定。同一天多次进入不会重新领配额；未完成任务不跨日续传，下个计划日按最新进度重排。

07图例与约定

实线 = 组合关系。子结构内嵌在父 JSON 里，删父即删子。
虚线 = 按 id 引用。实体独立存在，删除一方不会带走另一方。
红虚线 = 失败、淘汰或失效路径，不产生新的有效数据。
PK主键；FK 外键；PK·FK 既是主键又是外键（复合主键的一列）。
1 / N / M 标在线端：短横表示「一」，爪形分叉表示「多」。
状态颜色：灰=中性、绿=一致/完成、琥珀=待处理、蓝=进行中、红=异常或失效。

图由源码字段与调用顺序手工绘制，不是自动导出；字段名保持与备份格式一致，因此可直接对照 library.json 阅读。

数据来源：Library.java（顶层键与不变量）、 ReviewPlans.java（plan / state / day / event）、 Repository.java（磁盘状态与恢复）、 JsonStoreBackend.java（世代与提交结果）、 SecureSettings.java（凭据域）。
